# Authoritative World Sources

Edit the small JSON arrays here, then run from the project root:

```text
python tools/build_world.py
```

The builder validates the combined world and generates the six category files under
`data/world/`. Do not edit those generated files directly.
The same command builds `data/source/encounters/wild/*.json` into
`data/encounters/wild.json` and validates Zone encounter references before writing outputs.

## File Organisation

| Source directory | Grouping | Generated collection |
| --- | --- | --- |
| `containers/buildings/` | Buildings grouped by settlement or route | `containers/buildings.json` |
| `containers/instances/` | One natural instance per file | `containers/instances.json` |
| `containers/routes/` | One route per file | `containers/routes.json` |
| `containers/settlements/` | One settlement per file | `containers/settlements.json` |
| `connections/` | Connections grouped by area | `connections.json` |
| `portals/` | Typed Warp links grouped by area | `portals.json` |

Each JSON file contains an array, even when it holds one record. Nested folders are
supported. Keep at least one JSON file in each category; use `[]` if a category is empty.

The initial Connection and Portal groups use the area of the first authored endpoint.
If a normal link's first endpoint is unfinished, use its other authored endpoint. Author each
cross-area relationship once and reference its ID from the relevant Zones. File placement
does not determine graph ownership or direction. Buildings in Viridian Forest gatehouses
are grouped with Route 2; the Victory Road gate is grouped with Route 22.

The builder sorts top-level objects by ID and Warp links by type and their ordered endpoints.
It preserves each link's endpoint order and every nested array, including ledges' ordered
endpoints. File order never defines progression or traversal behaviour.

Draft-mode validation permits unfinished endpoint references as warnings. Other validation
errors prevent generation. Diagnostics identify source files for JSON, shape, and duplicate
record errors, and collection/record references for assembled-world validation errors.

## Before Committing or Packaging

```text
python tools/build_world.py --check
python -m unittest discover -s tests -p "test_*.py"
lua tools/test.lua
lua tools/load_world.lua
```

Check mode validates sources and compares generated bytes without modifying files. It fails
if any generated category is missing or stale. Build after source edits, then commit the
source files and generated outputs together. Package the generated `data/world/` JSON files
and `data/encounters/wild.json`
and the five generated `data/acquisitions/*.json` collections
for the runtime; source files and Python are development tools, not runtime requirements.

`--strict` rejects unfinished references and is expected to fail while the draft world has
known missing destinations. `--source PATH` and `--output PATH` support isolated builds;
these options now name the data roots containing `world/` and `encounters/` (defaults:
`data/source/` and `data/`). Generated files must not be inside the source root.

## Typed Warp Links

Author one object per link in the `portals/` source arrays:

```json
{"type": "normal", "warps": ["warp_a", "warp_b"]}
```

`normal` creates both A-to-B and B-to-A routes. For a one-way drop, use:

```json
{"type": "drop", "warps": ["warp_departure", "warp_landing"]}
```

Only the first-to-second route is created for a drop. Multiple links may arrive at one
landing; each Warp may have at most one outgoing route. Landing-only and unpaired Warps
are valid. Unknown types, malformed links, and duplicate outgoing routes are rejected.
The file name `portals.json` remains unchanged, but bare two-element arrays are no longer
accepted. Mansion-specific drop records await verification and world authoring.
